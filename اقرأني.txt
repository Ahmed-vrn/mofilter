النقل عبر GitHub (اختياري)
--------------------------
 يمكن رفع المشروع إلى مستودع GitHub ثم استنساخه على أي جهاز:

     git clone https://github.com/<USER>/<REPO>.git mofilter
     cd mofilter
     bash "مفلتر السيرفرات"

  • المستودع الخاص (Private) يتطلب تسجيل دخول عند الاستنساخ (SSH أو توكن).
  • github.json مستثنى في .gitignore ولا يُرفع أبدًا (يحتوي توكنًا سريًا).
  • البديل الآمن: github.example.json (قالب بلا توكن).
  • للتحقق قبل الرفع:
        git ls-files | grep github.json || echo "سليم: التوكن غير مضمّن"
   • يمكن أيضًا إرفاق الحزمة في Release على GitHub وتنزيلها بـ gh:

        gh release download v1.4.1 -R <USER>/<REPO>


التشغيل على الجهاز الآخر
------------------------
افتح طرفية داخل هذا المجلد ثم نفّذ:

    bash "مفلتر السيرفرات"

خيارات إضافية:

    bash "مفلتر السيرفرات" --no-open        # تشغيل الخادم فقط بلا نافذة
    bash "مفلتر السيرفرات" --no-desktop     # دون تثبيت اختصار سطح المكتب
    bash "مفلتر السيرفرات" --port 9000      # منفذ مخصص
    bash "مفلتر السيرفرات" --keep-skill     # أبقِ المهارة كما هي دون ترقية
    bash "مفلتر السيرفرات" --help           # المساعدة
    bash "مفلتر السيرفرات" --version        # رقم الإصدار

ما يحدث تلقائيًا عند التشغيل:
  - يُفكّ التطبيق إلى:   ~/.local/share/mofilter/vpn-web-app.py
  - تُثبَّت المهارة في:  ~/.config/opencode/skills/vpn-list/
      • إن لم تكن موجودة: تُنسخ كاملة.
      • إن كانت أقدم من إصدار الحزمة: تُرقّى مع نسخة احتياطية في
        ~/.local/share/mofilter/skill-backup-… (احتفظ بها للرجوع).
      • لإبقائها كما هي: أضف --keep-skill
  - يُثبَّت تطبيق سطح المكتب:
      • ~/.local/share/applications/mofilter.desktop
      • اختصار على سطح المكتب: «مفلتر السيرفرات»
      • أيقونة في ~/.local/share/icons/hicolor/…/apps/mofilter.png
  - تُفتح نافذة تطبيق مستقلة (بلا شريط عنوان ولا متصفح ظاهر)


تطبيق سطح المكتب
----------------
بعد أول تشغيل ستجد «مفلتر السيرفرات» في قائمة التطبيقات وعلى سطح المكتب.
انقر الأيقونة فقط — لا طرفية ولا أوامر.

  • تُفتح نافذة مستقلة بعنوان «مفلتر السيرفرات — لوحة التحكم».
  • الخادم المحلي يبدأ تلقائيًا على منفذ حر، ويُغلق مع إغلاق النافذة.
  • النقر مرة أخرى يفتح نافذة جديدة على نفس النسخة العاملة.
  • إن لم يوجد Chrome/Chromium يُستخدم Firefox أو المتصفح الافتراضي.
  • السجل: ~/.local/share/mofilter/desktop.log

تشغيل يدوي بلا نافذة (للاختبار أو من SSH):

    ~/.local/share/mofilter/mofilter-desktop --no-window

إعادة تثبيت الاختصار بعد نقل المجلد:

    bash desktop/install-desktop.sh

إزالته:

    rm ~/.local/share/applications/mofilter.desktop
    rm ~/Desktop/"مفلتر السيرفرات.desktop"
    rm -rf ~/.local/share/mofilter

الوضع الروسي — «تحديث روسي» (الأهم)
-----------------------------------
هذا الوضع صُمّم للبحث عن اشتراكات حديثة تعمل في روسيا، وليس مجرد
تحديث القائمة القديمة. عند الضغط عليه يحدث التالي بالترتيب:

  1) بحث جديد في ~25 مصدرًا، منها قوائم روسية متخصصة:
       - Prometheus / AetrisVPN / StekloVPN
       - igareck: WHITE-SNI-RU، WHITE-CIDR-RU، Vless-Reality-White
       - gitverse: whitelist، kizyak، PizdukVPN
       - wlunlocker: whitelist_all + CIDR-RU (أفضل نسبة SNI روسي حاليًا)
       - FLAT447: WHITE_LITE (قائمة بيضاء للجوال)
       - قوائم إضافية: BLACK_VLESS_RUS_mobile، WHITE-SNI-RU-all
  1ب) اكتشاف تلقائي على GitHub (مرة كل 24 ساعة):
       - يبحث في المستودعات الحديثة الموسومة: free-vpn-russia،
         vpn-russia، russia-vpn، vless-reality.
       - يفحص ملفات الاشتراك فيها ويقبل فقط ما يحمل نسبة SNI روسية
         معقولة، بحد أقصى ~1200 رابط، فلا تتضخم القائمة.
       - المصادر المكتشفة تُخزَّن في sources_ru_discovered.txt.
  2) دمج الروابط الجديدة مع الروابط المخزّنة مسبقًا (بلا تكرار)
  2ب) إزالة التكرار قبل الفحص (انظر القسم التالي)
  3) فلترة SNI حسب المشغّل الروسي (القائمة البيضاء)
  4) فحص الاتصال 3 جولات لكل سيرفر
  5) كشف الخنق الصامت (TSPU) اختياريًا
  6) كتابة القائمة + النشر إلى GitHub تلقائيًا

خيارات الوضع الروسي في الواجهة:
  • مشغّل: تلقائي / MTS / Мегафон / Билайн / Tele2
      - «تلقائي» يكتشف بيئة شبكتك: إن كانت قائمة بيضاء يفلتر SNI روسي.
      - MTS وМегафон يفرضان فلترة SNI روسية صارمة دائمًا.
      - Билайн وTele2 يفحصان دون فلترة SNI صارمة.
  • كشف الخنق: يكشف السيرفرات التي تعمل لكن سرعتها مقيّدة.
  • مصادر عميقة: يضيف الطبقة العميقة (8 قوائم كبيرة، منها bypass-all
      من rjsxrd: vless + shadowsocks + hysteria2). روابط أكثر لكن
      البحث أبطأ — يُحفظ الاختيار في الإعدادات.
  • حد: أقصى عدد روابط للفحص (0 = الكل).
      الفحص الكامل لـ1500+ رابط قد يستغرق ساعات.
      للفحص السريع استخدم 100–300.
      عند تحديد حد، تُرتَّب الروابط بحيث تُفحص ذات SNI الروسي أولًا.

مهم جدًا: نتيجة الفحص تعتمد على الشبكة التي يعمل منها التطبيق.
  - على شبكة جوال روسية: النتائج تعكس الواقع الروسي (الأدق).
  - على شبكة أخرى: النتائج تعكس تلك الشبكة، وقد تختلف تمامًا.


إزالة التكرار قبل الفحص
------------------------
قبل أي فحص، يمرّر التطبيق الروابط على مرحلة تنظيف تمنع
إعادة فحص نفس الخادم مرات كثيرة. ثلاثة مستويات:

  • ذكي (الافتراضي): المفتاح = (المضيف، المنفذ، SNI)
      يدمج الروابط المتطابقة في الخادم وSNI، ويُبقي النسخ
      المختلفة في SNI لأنها قد تنجح أو تفشل حسب الشبكة.
  • حسب الخادم: المفتاح = (المضيف، المنفذ) — أقوى توفير للوقت،
      لكنه قد يحتفظ بنسخة واحدة فقط لكل خادم.
  • نصي فقط: لا يدمج إلا الروابط المتطابقة حرفيًا (الأكثر تحفظًا).

عند وجود عدة نسخ للمفتاح نفسه، يُفضّل التطبيق النسخة التي
يطابق SNI الخاص بها قائمة المشغّل الروسي، ثم أي نسخة لها SNI.

أرقام حقيقية من قائمتك المحدّثة (2694 رابطًا بعد دمج المصادر الجديدة):
    نصي فقط     : 2679 → 2679   (أُزيل 0)
    ذكي         : 2679 → 994    (أُزيل 1685 — 63%)
    حسب الخادم  : 2679 → 966    (أُزيل 1713 — 64%)

ملاحظات:
  - الإزالة تُطبَّق على «تحديث روسي» و«إعادة فحص المحفوظ».
  - القائمة المخزّنة نفسها تُنظَّف بعد التشغيل، فلا تتضخم مستقبلًا.
  - إن أردت أقصى تدقيق (فحص كل نسخة) اختر «نصي فقط» مع «حد = 0».
  - الفحص الجزئي (عندما يكون «حد» أكبر من صفر) لا يُنشر تلقائيًا
    إلى GitHub، حفاظًا على القائمة العامة من الاستبدال بنتيجة جزئية.


تحسينات الروابط والمصادر
------------------------
  • استخراج أذكى: يقرأ الروابط داخل Markdown وJSON وHTML والقوائم
    المكتوبة بصيغ مختلطة، ويزيل علامات الترقيم والاقتباس الزائدة.
  • تعقيم قبل الفحص: تُسقط الروابط التي لا تستطيع النوى بناء اتصال
    منها (منفذ/معرّف ناقص) فلا تُهدر وقتًا على صيغ تالفة.
  • أولوية روسية عند الحد: إذا وضعت «حد» = 200 مثلًا، تُفحص أولًا
    الروابط ذات SNI من القوائم البيضاء الروسية، لا أول 200 أبجديًا.
  • قائمة SNI موسّعة: أضيفت نطاقات روسية معروفة (x5.ru، max.ru،
    yandex، sber، ozon، wildberries…) إلى ملفات المشغّلين.
  • سجل صحة المصادر: data/source_health.json يبيّن كل اشتراك وعدد
    روابطه الجديدة أو سبب فشله، دون أن يوقف التشغيل.
  • فحص المصادر يدويًا:
        python3 ~/.config/opencode/skills/vpn-list/scripts/sources_ru.py --refresh
        python3 ~/.config/opencode/skills/vpn-list/scripts/sources_ru.py --discover --force
  • القوائم الكبيرة جدًا متاحة اختياريًا: فعّل مربّع «مصادر عميقة» في
    الواجهة، أو من الطرفية:
        VPN_DEEP=1 bash "مفلتر السيرفرات"
        python3 .../scripts/run.py --single --deep-sources
    الطبقة العميقة تضم 8 مصادر، منها whoahaow/rjsxrd
    (bypass-all.txt: 474 رابطًا صالحًا، ~25% نجاة فعلية في عيّنة قياس).


خيارات --single و --no-confirm
------------------------------
هذان الخياران تمرّرهما الواجهة تلقائيًا عند تشغيل run.py:

  - --single       ينفّذ دورة فحص واحدة ويكتب النتيجة فورًا
                   (بدلًا من الوضع الافتراضي متعدد المراحل).
  - --no-confirm   لا يسأل أبدًا على stdin ويعتبر أي تأكيد «نعم».
                   ضروري لأن الواجهة تشغّل العملية بـ stdin=DEVNULL،
                   فأي سؤال انتظارًا لإدخال سيجعل التشغيل يتوقف.

من الطرفية يمكن استخدامهما مباشرة:

    python3 ~/.config/opencode/skills/vpn-list/scripts/run.py --single --no-confirm


ماذا يفعل التطبيق
-----------------
  - عرض السيرفرات العاملة مع البحث والنسخ (نسخ سيرفر واحد أو الكل)
  - إزالة تكرار قبل الفحص بثلاثة مستويات (ذكي/خادم/نصي)
  - خمسة أوضاع تشغيل:
      • تحديث روسي       (بحث + دمج + فلترة روسية) ← الموصى به
      • تحديث كامل        (فحص القائمة كاملة — قد يستغرق وقتًا)
      • فحص سريع          (أول 150 رابطًا)
      • إعادة فحص المحفوظ (من ملف الروابط السابق)
      • مصدر مخصص         (رابط اشتراك تكتبه بنفسك)
  - سجل تشغيل حيّ مع شريط تقدّم المراحل (0/6 → 6/6)
  - نشر إلى GitHub يدويًا، أو تلقائيًا بعد كل تحديث ناجح
  - نسخة أمان تلقائية قبل كل تشغيل (القائمة + النتائج + الروابط)
    واستعادتها عند الفشل
  - تنزيل الملفات: vpn-servers.txt، Clash، التقسيم حسب الدولة…

ملاحظة عن الإحصاءات:
  - بطاقتا «مستقرة» و«كل العاملة» تعرضان «—» إن لم تكن نتائج
    آخر فحص متاحة. تظهر الأرقام بعد أول تحديث ناجح.


هل يحتاج OpenCode أو DeepSeek Harness؟
--------------------------------------
لا. التطبيق مستقل تمامًا:

  - التطبيق: بايثون 3 (المكتبة القياسية فقط) + HTML/CSS/JS مدمجة
    + سكربتات المهارة. لا حزم خارجية ولا pip.
  - المهارة تُنسخ إلى: ~/.config/opencode/skills/vpn-list
    وهذا مجرد مسار تقليدي يُنشأ تلقائيًا، ولا يتطلب وجود OpenCode.
  - لا يوجد أي استيراد لـ opencode أو deepseek أو dsh في السكربتات.
  - إن ثبّت OpenCode أو DSH لاحقًا، ستجد المهارة جاهزة في مكانها
    ويمكن استخدامها من داخل الوكيل مباشرة.

تم اختبار ذلك في بيئة فارغة تمامًا (HOME بلا .config وبلا أي وكيل):
  - التطبيق: 200 OK، skill_ok = true، الإصدار 1.4.1
  - run.py --help يعمل بلا أي وكيل
  - لا استيرادات خارجية

ماذا يحدث عند أول تشغيل على جهاز نظيف:
  1) فك التطبيق إلى ~/.local/share/mofilter/vpn-web-app.py
  2) نسخ المهارة إلى ~/.config/opencode/skills/vpn-list (إن لم تكن)
  3) تحذير أن النوى غير موجودة
  4) بدء الخادم على 127.0.0.1:8080 وفتح المتصفح
     (أو طباعة الرابط إن لم يوجد xdg-open)

أول «تحديث روسي»:
  - ينزّل sing-box (~78 MB) وXray (~35 MB) تلقائيًا (~50 MB تنزيلًا)
  - إن فشل التنزيل: رسالة واضحة + استعادة القائمة السابقة دون تعطّل.


متطلبات الجهاز الآخر
--------------------
مطلوب:
  - Linux + bash
  - python3 (3.8 أو أحدث) — لا حزم Python إضافية
  - أدوات أساسية: tar, base64, sed, mktemp, curl
  - متصفح لفتح الواجهة
  - مساحة قرص: ~120 MB (النوى وحدها ~113 MB بعد الفك)
  - إنترنت عند أول تحديث: يُنزَّل sing-box وXray تلقائيًا (~50 MB)
    ثم تعمل الفحوصات لاحقًا دون إعادة تنزيل

غير مطلوب إطلاقًا:
  - OpenCode · DeepSeek Harness · Node.js · pip
  - صلاحيات جذر · systemd · سطح مكتب

حالات خاصة:
  - بلا إنترنت      : الواجهة تعمل، والفحص لا.
  - بلا python3     : يتوقف فورًا برسالة «خطأ: python3 غير مثبت».
  - بلا github.json : زر النشر معطّل، والنشر التلقائي لا يعمل.
  - جهاز ARM        : مدعوم (تُنزَّل نسخ arm64).
  - بلا واجهة رسومية: يطبع الرابط؛ افتحه بمتصفح محلي أو عبر SSH tunnel.
  - الوصول من الهاتف: غير ممكن — الخادم يستمع على 127.0.0.1 فقط.


حلّ المشكلات
------------
  • «python3 غير مثبت»
      ثبّته من مدير حزم التوزيعة (مثال: sudo pacman -S python).

  • «تعذّر فك الحزمة»
      الملف تالف أو نُقل ناقصًا — أعد نسخه كاملًا.

  • المنفذ 8080 مشغول
      التطبيق يختار منفذًا حرًا تلقائيًا ويعرضه في الطرفية،
      أو حدّده أنت بـ --port.

  • النشر إلى GitHub يفشل
      تحقّق من وجود ~/.config/vpn-list/github.json وصلاحياته 600،
      ومن أن التوكن ما زال صالحًا.

  • «لا توجد سيرفرات»
      شغّل «تحديث روسي» وانتظر انتهاء الفحص.

  • الفحص بطيء جدًا
      ضع «حد» = 200 أو 300 بدل 0.

  • نوى الفحص لا تُنزَّل
      تحقّق من الاتصال بالإنترنت، ثم أعد تشغيل التحديث.


أمان — مهم
----------
  - github.json يحتوي توكن GitHub بنص صريح (صلاحياته 600).
  - لا تشاركه، ولا تضعه في مستودع Git، ولا ترفعه إلى أي خدمة.
  - إن تسرّب التوكن: أبطِله من إعدادات GitHub وأنشئ توكنًا جديدًا،
    ثم حدّث الملف.
  - التطبيق يعمل محليًا فقط على 127.0.0.1 ولا يفتح منفذًا للشبكة.
  - يرفض أي طلب بـ Host أو Origin غريب (حماية من صفحات الويب الخارجية
    ومن DNS rebinding)، ويرسل رؤوس حماية للواجهة (CSP وX-Frame-Options).

    يرفض البناء إن اختلف إصدار التطبيق عن skill/.version،
    ويحفظ النسخة السابقة باسم «مفلتر السيرفرات.bak».
  - صيانة شاملة (إصدارات + إصلاحات + اختبارات + بناء):
        bash fix-mofilter.sh
  - بنية المشروع:
        vpn-web-app.py     التطبيق
        skill/             مهارة vpn-list (run.py + المصادر + المراجع)
        desktop/           مشغّل سطح المكتب + الأيقونات + المثبّت
        packaging/         قالب رأس الحزمة المتنقلة
        build_package.sh   بناء الحزمة المتنقلة
        test_selftest.py   اختبارات الوحدة
